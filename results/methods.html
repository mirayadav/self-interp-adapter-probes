A step-by-step account of what we ran and why — starting from what the original paper does, then what we reproduced, then each experiment we added on top, in the order it was built.

Part 0 — Background

What the paper does

Inside a language model, every token at every layer has an activation — a list of 4,096 numbers. Nobody knows what any given one means. Normally you find out by having a human or another AI guess a label for it, which is slow and unreliable.

The paper's idea: get the model to describe its own activation. You can't just hand a raw activation to a model, because it doesn't look like anything the model reads — it lives in a different space from word embeddings. So they train a tiny translator that converts an activation into something the model can read, then drop it into a prompt that asks "what does this mean?"

1
Take hthe activation you want explained
2
Translatea tiny adapter turns h into a fake "word"
3
Injectslot it into "What is the meaning of ___?"
4
Readthe model writes a description

The translator is deliberately tiny — it has one scaling number and one 4,096-long vector, and that's all:

f(h) = α · (h / ‖h‖) + b
        └─ the activation ─┘   └─ a fixed vector, the same every time ─┘

Two things to notice, because everything below depends on them. First, the activation gets divided by its own length before use, so only its direction matters, never its size. Second, b is a constant — it is added identically no matter what activation you feed in. It's a learned "house style" for how to answer.

The open question

The paper reports that this constant b accounts for about 85% of the improvement over an untrained baseline. They read that as: b teaches the model how to interpret, and the activation supplies what to say.

That's plausible. But it isn't tested. All their evidence shows descriptions match activations across many examples — which is also what you'd see if the model were mostly pattern-matching from a prior. Nobody ever took a single activation, changed it on purpose, and checked whether the description changed too.

So that's the whole project: nudge an activation in a known direction, and watch whether the description follows.

Part 1 — Reproduction

First, does their released version work?

Before testing anything new, we had to confirm the published artifact behaves as advertised. Otherwise every later result is meaningless.

Helpfully, the authors released everything — code, data, and the trained adapters — so we trained nothing. We downloaded their adapter and ran their own evaluation.

What we did

Took 1,000 Wikipedia topics the adapter had never seen. For each: prompt the model with "Tell me about {topic}", grab the activation at layer 19, run it through the adapter, inject it, and let the model write 6 descriptions. Then check whether those descriptions are enough to identify the original topic out of all 49,637 candidates.

How "identify the topic" is actually checked

Nothing compares strings, and nothing checks whether the description mentions the topic by name. It's all done by meaning:

  1. Build an index once. Each of the 49,637 topics becomes a short document — its title plus its first 8 alternate descriptions from the dataset. All of them get converted into vectors by a sentence-embedding model.
  2. Convert each generated description into a vector the same way.
  3. Compare it against all 49,637 documents and sort them from most to least similar.
  4. Find where the true topic landed in that ranking.
  5. Best of 6: the topic counts as identified if any of its six descriptions ranked it inside the cutoff.

So the three result columns are just three cutoffs:

Two caveats on the metric. Best-of-6 flatters it — a topic only needs one of six attempts to succeed, so single-shot accuracy would be noticeably lower. (The paper generates 6 candidates too, by varying the injection strength where we vary by sampling, so the comparison to their number is fair.) And because matching is by meaning rather than by name, a description that never says the topic's name can still rank it first — which is the point, since the model is describing an activation, not reading a label.

We ran three versions to separate out what's doing the work:

  • Trained — the real released adapter.
  • Untrained — no adapter at all, just the raw activation. The paper's baseline.
  • Bias only — feed in a zero activation, so all the model receives is the constant b. This one is ours, and it turned out to matter.

Reproduction passes. The released adapter does what the paper says. We can trust it as a foundation.

Part 2 — The experiments we added

Six experiments, in the order we ran them

None of these are in the paper. Each one exists because the previous one raised a question.

1 · How much room does the activation even have?

The question

If the constant b is huge and the activation's contribution is tiny, the description might be mostly pre-written. Can we measure that directly?

What we did

Answered it without running the model at all. Because the activation is divided by its own length before use, its contribution always has exactly the same size — call it α — no matter which activation you feed in. And b never changes. So both are just numbers sitting in the 19 kB adapter file. This ran on a laptop in seconds.

Only the ratio between them means anything. The raw sizes (α = 7.18, ‖b‖ = 20.87) are in arbitrary units — there's no standard scale for a model's internal space, so neither number is interpretable alone. What matters is how big the activation's contribution is relative to the constant:

Where those two numbers come from

The share. Squaring the formula gives ‖f‖² = α² + 2α⟨ĥ,b⟩ + ‖b‖². Averaged over all possible activations the middle term disappears — b is one fixed vector while the activation direction ranges over every direction equally, so it points with and against b equally often. That leaves a clean right-angle split, α² + ‖b‖², and the activation's share is α²/(α²+‖b‖²) = 10.6%.

The gap. Every possible output lies on a sphere of radius α centred on b. Viewed from the origin, the furthest a direction can swing is where your line of sight just grazes that sphere — the tangent, at sin θ = α/‖b‖. That's 20.1°, so two outputs can differ by at most twice that.

Both formulas contain only the ratio, which is why it's the number worth quoting:

We checked the algebra against the model rather than trusting it: sampling 1,000 random activations and measuring how similar their outputs actually were gave 0.89426, against a predicted 0.89429 — and no sampled output fell outside the 20.1° bound.

What we found

The activation is about a tenth of what the model receives; the constant is the rest. Geometrically, every possible input the model can be handed lives inside a single 40-degree cone. Two completely unrelated topics arrive looking almost identical.

But this does not mean the prior wins. Part 1 showed the model picks the right topic out of 49,637 — using only that cone. So it must be extremely sensitive to small differences. A tenth of the signal is not a tenth of the meaning: a small, consistent nudge in a 4,096-dimensional space can carry a great deal, and the model is nonlinear enough to read it. This measures how much room the activation has, not how well the room is used — which is exactly why the sweep is needed. It also predicts the sweep should work.

2 · What does the model say when you give it nothing?

The question

If b really carries 85% of the benefit, what does it say on its own?

This one is not ours. The paper already runs it — it applies the adapter to a zero vector and reports generic descriptions (Appendix J), and it already concludes that the bias supplies format while the activation supplies semantics. It supports that with a sharper test than this one: train on ALL-CAPS labels and the outputs come out both capitalised and semantically correct, which separates the two contributions cleanly (Appendix I). All we add is a number.

What we did

Fed the adapter a vector of all zeros, so the model receives only b and no information whatsoever about any activation.

What we found

Fluent, confident, specific descriptions — "the director of the 1967 film Blow-Up", "the journalist who coined the term 'tropism'". And a top-guess accuracy of 0.0%. They're completely made up.

This confirms the paper rather than correcting it. The authors say the bias supplies format and the activation supplies semantics; 0.0% puts a hard number on the second half — the bias carries no identifying information at all. Someone reading "85% of the improvement" in isolation might assume the prior does most of the work, but the paper never claims that, and this agrees with the paper.

The one thing beyond restatement: these outputs aren't merely generic, they're confidently fabricated — real-sounding people, films and dates corresponding to nothing. A prior that invents rather than hedges matters for the paper's own motivation of catching a model that misreports itself.

3 · Building the nudges — and the trap we nearly fell into

The question

To nudge an activation "toward a concept", we need a direction that means something — a steering vector. Where do those come from?

What we did

Used an open dataset called AxBench: for each of ~2,000 concepts it provides example answers that express the concept and example answers that don't. Average the activations of the ones that do, and you get a direction pointing at that concept.

Before using them, we checked the data. Four problems, one serious.

Problem 1 · the dangerous one
All the "positive" examples are written in the same voice

AxBench's positives were generated by an AI told to express a concept, so they share a flowery register the negatives lack. The word "akin" appears in 17.2% of positives and 0% of negatives. Positives are 46% longer.

We tested how bad this is: a classifier shown concepts it had never seen could still tell positives from negatives 97% of the time — purely from writing style.

Why that nearly ruined everything: our steering vectors would have encoded "flowery AI voice" rather than any concept. The sweep would then have shown a strong, consistent effect — and passed our safety checks, because a writing style is a real and consistent direction. We'd have reported a confident false positive.

Problem 2 · unfixable, so declared
The questions differ too, not just the answers

Positives and negatives don't answer the same questions — the two question pools don't overlap at all, and questions were picked to suit their concept. So the direction partly captures "what these prompts were about" alongside "what the answer expressed." Those point the same way semantically, so it's a caveat rather than a wrecking ball, but it can't be removed.

Problem 3 · the obvious fix that failed
Making the lengths equal doesn't help

Since positives run 46% longer, we tried trimming everything to the same length. Style separability barely moved — 97% before, 97% after. Length isn't the mechanism, so we dropped this step entirely.

Problem 4 · the proxy lied
Inside the model it was four times worse than the text suggested

Everything above was measured on the text. When we finally measured the real activations, every concept vector turned out to be very nearly the same vector.

How we measured it: average all 60 concept vectors together. If they genuinely pointed in different directions they would mostly cancel out — for 60 unrelated vectors the average shrinks to about 1/√60, or 13% of a typical length. Instead the average came out at 96% of a typical vector's length. Almost nothing cancelled.

That 96% is a ratio of lengths, so it doesn't mean only 4% was left. What remains after subtracting the shared part sits at roughly a right angle to it, so the leftovers work out to 28% by length, about 8% by energy. The concept signal was real, but submerged under a nine-times-larger component that every concept shared.

Wait — isn't a strong average what we want?

Worth pausing on, because there are two different averages here and only one of them should be large.

Averaging within a concept is the good one. Take the 108 answers that express "gambling", average their activations, and you get a vector that should strongly represent gambling. Individual quirks cancel; what the examples share survives. That's the whole method, and it works as intended.

Averaging across concepts should give almost nothing. Gambling, plant viruses and weekends are unrelated, so their sixty vectors ought to point sixty different ways and largely cancel. The 96% figure measures this second average — and it says they didn't cancel at all:

Two unrelated conceptsrawafter fix
gambling ↔ plant viruses0.920−0.220
gambling ↔ temperature measurement0.931−0.135
mental health ↔ temperature measurement0.947−0.003

"Online gambling" and "the classification of plant viruses" had 92%-identical vectors. Steering with one would have done nearly what steering with the other does. Averaging within each concept had succeeded at cancelling noise — but what it converged on was mostly something every concept shares.

Only part of that is this dataset's fault. Activations inside a transformer carry a large common component no matter what they encode: earlier, in an unrelated sanity check, activations for William Wallace and photosynthesis came out 99% aligned. AxBench's uniform writing voice sits on top of that.

The fix

Subtract the average of all the concept vectors from each one. Whatever they all share — the generic activation structure, the voice, the format — cancels, and what's left is what makes each concept distinctive. This is the same trick the paper itself uses: its topic vectors are an activation minus the mean over all 50,000 topics.

Two checks that this removed noise rather than signal. First, the leftover similarities became semantically sensible — plant viruses and temperature measurement stay mildly related at +0.317 (both scientific), gambling and weekends at +0.237 (both leisure), while gambling and plant viruses go negative. Before the fix everything sat at 0.92 regardless of meaning. Second, rebuilding each vector from a different half of its examples gave a 94% match, so what survived is stable.

There's also a consequence specific to this experiment: without the fix, a concept's vector and the shared-voice vector would have been nearly the same thing — so the concept arm and the style control in experiment 5 would have moved together, and the control would have been worthless. The controls only mean anything because the two were separated first.

We also kept the discarded "shared voice" direction as a deliberate control — see experiment 5.

4 · Do these nudges actually change the model's behaviour?

The question

A direction that changes a description but nothing else would prove very little. We need independent evidence that the nudge does something real to the model first.

What we did

Forget self-interpretation for a moment. Just add the direction into the model mid-computation while it answers ordinary questions, and see whether the answers change. We swept the nudge strength — call it λ — from strongly negative to strongly positive, and also tracked whether the model was still writing coherent English.

What those two columns actually measure

"Concept present" — the score is essentially a multiple-choice question. Embed the model's answer, then compare it to the concept's own description and to 40 other concept descriptions. The score is the fraction of those 40 that the right one beats. 1.0 means the answer is closer to the right concept than to any alternative; 0.5 is a coin flip.

Why bother with the alternatives at all? Because the obvious approach — just measure similarity to the right concept — is not trustworthy. That number drifts upward whenever text merely gets longer or vaguer, so ordinary waffle would register as success. Adding wrong answers fixes it: generic drift lifts the right answer and the wrong answers together, so it cancels out and shows as no change. Only a genuine move toward this concept beats the alternatives.

Note the counts here: this screen tested all 60 shortlisted concepts, each scored against 40 alternatives drawn from the other 59. The set of 10 comes later — 11 of the 60 survived the coherence gate, and the strongest 10 went forward to experiment 5.

"Still coherent" — the fraction of adjacent word pairs in the answer that aren't repeats. 1.0 means nothing repeats; a low score means the model is looping.

Both are easier to read against real output. Same concept, four strengths:

This is exactly why the coherence column exists. At λ=2 the concept score is near its maximum (0.957) — precisely because the output is nothing but concept keywords. The concept metric looks best where the model has most thoroughly broken. Without the second column you would read that as the strongest result rather than the weakest.

Steering works — the concept reliably shows up in the model's answers. But push too hard and the model falls apart. Only the range up to about λ=1 is meaningful; beyond that we're measuring damage. The cutoff we used — coherence must stay above 60% of its unsteered value at every strength — is what cut 60 concepts down to 11.

Two more measures we tracked

The coherence score only catches repetition — fluent nonsense would sail through it. So we also fed every steered output back through the unsteered model and measured how improbable it found its own text. And because the concept score leans on one embedding model, we added a crude check with no embeddings at all: does the output literally contain the concept's characteristic words?

Keyword match matters more than it looks. One honest note on the filter. Although we tracked all four, only coherence was actually used to include or exclude a concept. Surprise and keyword match were recorded for interpretation but never gated anything, so the 60 → 11 cut was coherence alone.

5 · The main experiment: nudge the activation, read the description

The question

Everything so far was setup. Now: take an activation, add the concept direction at increasing strength, and see whether the self-description follows.

Two different things, easy to confuse

Topics are Wikipedia articles — Chu Suiliang, Robert Menzies, John Dory. They supply the activation being described. There are 30 of them, from the same dataset as Part 1.

Concepts are the steering directions — "economic terms related to taxes and subsidies". They supply the nudge. There are 10, from AxBench, built in experiment 3.

Every topic is crossed with every concept: 10 × 30 = 300 combinations, each at 11 nudge strengths, each generating 6 descriptions, across 4 versions of the experiment.

The ten concepts, and how distinct they really are

Small enough to list in full. "Rise" is how strongly each one steered the model's behaviour in experiment 4; "closest other" is how similar its steering vector is to the most similar of the other nine (0 = unrelated, 1 = identical).

What that costs. Three things, all in the conservative direction. The effective number of independent concepts is ~9 rather than 10, so the confidence intervals — which treat concepts as independent — are slightly optimistic. The duplicate pair sits in each other's comparison pool, making each nearly impossible to rank first, which depresses their scores rather than inflating them. And the two weakest steerers in the table (0.240, 0.219) are barely above the shared-voice control's 0.153, so the strong aggregate result leans on the top half of this list.

What we did

For scoring, we didn't just ask "does this description look like the concept" — that number creeps up whenever text gets longer or vaguer. Instead we asked does it look more like the right concept than like the other concepts. Generic drift then lifts everything equally and shows up as no change.

Correction worth stating plainly. We intended to compare against 40 other concepts, and the behavioural screen in experiment 4 did exactly that. But the sweep's scoring only had the 10 swept concepts available to draw from, so it was in fact a 9-way comparison, not 40-way. Two effects, pulling opposite ways: a smaller pool is easier to win, which inflates the absolute numbers; but the 10 include near-duplicates ("calls to action for clicking links" versus "phrases that prompt clicking on links", 0.62 similar), which makes it harder. Both apply identically at every nudge strength and to every control, so the shape of the result — and the flat controls — are unaffected. The absolute values should be read as approximate.

correction · this control is broken
The shared-voice column is 0.500 by arithmetic, not by measurement

Look at how exact it is — 0.5000 at every single strength. That is not what a measurement looks like, and chasing it down showed why.

The shared-voice direction is one vector, the same for all ten concepts. So for a given topic and strength, this arm generates the identical description ten times over. We then score that one description against each of the ten concepts in turn, each against the other nine — and that is forced to average to exactly a half. Every "concept A beats concept B" is matched by a "concept B loses to concept A", so the wins and losses cancel by construction.

It would read 0.500 even if the shared direction had shoved every description hard toward one concept. The column contains no information, and we exclude it from the conclusion. The fix is to draw the comparison pool from concepts outside the ten being tested, so wins and losses can no longer cancel; the code now does this, but the numbers above predate it.

The last column is the honest caveat. Feeding the nudge alone jumps straight to 0.796 and stays there. At λ=0.3 the real experiment is at 0.558 — far below that — so the activation is still doing most of the work. But by λ=2 the two have converged, meaning the activation has been drowned out.

The description tracks the activation, specifically and in both directions, and a random direction does not produce the same effect. Trust the range up to λ≈1; past that the model is just reading the nudge.

What the broken control costs us. The random column still rules out the biggest worry — that descriptions shift whenever you disturb the activation at all. But the shared-voice column was there to rule out something subtler: that descriptions follow any direction the model genuinely represents, not this concept in particular. That question is now unanswered. A random direction cannot stand in for it, because the model has never represented one.

7 · But how big is the effect, really?

The question

"Real and consistent" isn't the same as "large". How much of what the model says is actually driven by the nudge?

What we did

Took all 19,800 descriptions and split up the variation between them: how much is explained by the constant prior, by which topic it started from, by the nudge, and by plain randomness in generation.

The effect is real but small. The nudge accounts for well under 1% of the variation between descriptions, while the starting topic accounts for 31%. It's consistent, directional and behaviourally calibrated — but it is not what dominates what the model says.

Part 3 — Verdict

What all this adds up to

It supports the paper. Self-interpretation isn't just reciting a prior. Change the activation and the description follows, in the right direction, by the right amount, at the same point the model's behaviour changes. And the three ways this could have been a mirage — a generic reaction to disturbance, a reaction to any real direction, or the activation being drowned out — were each checked and ruled out.

It confirms the paper's account of the bias. The authors already say the bias supplies format and the activation supplies semantics, and already show the zero-vector behaviour. Experiment 2 adds a number to that — the prior identifies nothing on its own — rather than overturning anything.

And it sets a ceiling. Experiment 7 says the nudge moves under 1% of what varies between descriptions. The signal is real; it is not loud.

What this is not

  • Not proof the model is reading its own mind. Steering vectors are blunt instruments. We showed descriptions respond to a controlled, independently checked change — no more.
  • We picked favourable concepts. Twice: first for being clean in the data, then for steering well without breaking fluency. Only 5 of the final 10 steered strongly, and two of the ten are near-duplicates of each other (similarity 0.97), so there are really about 9 independent concepts.
  • It's narrow. One model, one layer, one adapter, 10 concepts, 30 topics.
  • One data problem remains (problem 2 above) and can't be removed.

What we'd do next

The much stronger test is to intervene on something whose role inside the model is already independently established — a known circuit or feature — and ask whether the self-report describes that correctly. Steering vectors can only ever get you so far.

Part 4 — How it actually ran

Practical details

One embedding model, thenlper/gte-large, was used for every score in every experiment — topic retrieval in Part 1, the behavioural screen, and the λ-sweep. It's the paper's own choice, which keeps the reproduction comparable. Using one model throughout does mean the concept scores in experiments 4 and 5 share a dependency, which is why the keyword check above exists.

About 2,000 lines of Python across 12 modules. We didn't reuse the authors' code directly — it pulls in heavy GPU dependencies we didn't need — but we matched their conventions exactly so the numbers stay comparable.

Development happened on a 2019 Intel MacBook with no usable GPU, which forced a useful discipline: every script has a --smoke mode that swaps in a tiny 0.5B model on CPU. The outputs are gibberish, but it catches shape errors and wiring bugs before any money is spent. The whole pipeline ran end-to-end locally first.

The real run used a rented NVIDIA A40 (48GB) on RunPod. Choosing it involved a constraint that isn't documented anywhere obvious: no 48GB GPU offers persistent storage in its region. We took the bigger GPU over persistence, since rebuilding the machine takes 15 scriptable minutes while a memory ceiling is forever.

Everything ran as one detached script that writes a progress marker after each stage, so checking on it is a one-line query rather than babysitting a connection. Start to finish: 1 hour 45 minutes, about 80 cents for all 79,206 generations.

Things that cost us time

  • Updating the machine's settings wiped its SSH key — the update call replaces all settings rather than merging them, locking us out until restored.
  • The secret token looked broken but wasn't. Environment variables set on the machine aren't visible in SSH sessions; you have to read them from the running process.
  • The SSH port changes every restart.
  • The storage is network-backed — fine for loading a big model, painfully slow for installing packages, which made two installs look frozen when they were merely crawling.
