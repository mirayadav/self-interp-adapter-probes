Reading the Activation, Not the Prior

Project · Mechanistic interpretability, Llama 3.1 8B

Summary

I reproduced the main result from Self interpretation in language models via adapter probes and then ran an extension to test something the paper leaves open. The paper trains a tiny adapter, as few as d+1 parameters, that maps a model's internal activation back into its own embedding space so the model can describe what that activation represents. It works well, and in my reproduction it identifies the right topic out of 49,637 candidates 79.3% of the time, against 0.0% for an untrained baseline.

My critique is that the paper shows descriptions correspond to activations but never changes one activation on purpose to see whether the description follows. That leaves open the possibility that the model is pattern matching from a learned prior rather than reading the specific vector you hand it. To test this, I took an activation, added a steering direction for a known concept at varying strength, and measured whether the description moved toward that concept. I also verified separately that the same intervention changes the model's behaviour, which gave me a baseline for how much the description should move.

It does move, and the effect holds up under the checks I care about. Adding the direction shifts the description toward the concept while subtracting it shifts the description away, and a random direction of the same size does nothing, so the response is specific to the direction I chose rather than to disturbance in general. The description also shifts at the same intervention strength that changes the model's behaviour. While I think that is real evidence, the effect is small once you measure it against everything else that moves a description around, and getting to the answer at all meant catching two problems in my own setup that would each have produced a confident false positive.

This matters to me because the paper's framing is about trustworthy self report for alignment, the idea that a model could tell us what it is doing internally. If we want to rely on that to catch a model misrepresenting its own reasoning, a correspondence between description and activation is not enough. We need evidence that the report tracks the internal state, and I see this as one step in that direction rather than a resolution.

High level takeaways

  1. The description tracks controlled changes to the activation. Adding a concept direction moves the description toward that concept and subtracting it moves the description away, while a random direction of the same size does nothing at all. Under a paired bootstrap over 40 concepts the difference holds at every non zero strength (p = 0.0001 throughout), and it sits at exactly zero when I add nothing, which is the sanity check I most wanted to pass.

  2. The self report tracks behaviour almost point for point. Plotting the description curve against the behavioural curve across the same steering strengths gives a correlation of 0.997, with a mean absolute difference of 0.022. If the description had only registered the change long after the model's outputs visibly shifted, I would read that as the report picking up gross effects only, but it does not lag that way.

  3. The learned prior carries no information about the specific activation. Given a vector of zeros, the adapter still produces fluent and oddly specific descriptions that identify nothing at all, scoring 0.0% top 1. This agrees with the paper rather than contradicting it, since the authors already say the bias supplies format while the activation supplies meaning. What I would add is that the prior is not a neutral scaffold, because on its own it confabulates.

  4. The effect is real and small, and two of my own design choices nearly faked it. The nudge explains under 1% of the variation between descriptions, against 38% for which activation they started from. I also built one control that was mathematically pinned to chance and could not have detected anything, and one filter that selected against the effect it was meant to protect. I describe both below, since the process of catching them is the more transferable part of this work.

Background

Most interpretability work asks a human or a separate model to label internal features, which is slow and noisy, so this approach asks the model to do it instead. Following the Patchscopes framing, you take an activation from some layer, transform it with a learned mapping, and inject the result into a fixed prompt, "What is the meaning of ___?", as if it were a token embedding. The frozen model then describes it.

The mapping is deliberately tiny. The scalar affine version is

f(h) = α · (h / ‖h‖) + b

That is one scalar and one vector of 4096 numbers, and two properties of it matter for everything below. The activation gets divided by its own length, so only its direction carries information while its size is thrown away. The vector b is a constant that gets added identically no matter what you feed in, so it works as a learned default for how to answer.

The paper reports that this bias accounts for roughly 85% of the improvement over an untrained baseline, and reads it as the bias supplying format while the activation supplies meaning. They back that up with a zero vector test and, more convincingly, by training on labels written in capitals and showing the outputs come out both capitalised and semantically correct. I want to be precise here because I initially overstated it. The authors do not claim the prior does most of the semantic work, and my results agree with them.

What the paper does not do is intervene. All of its evidence has the form "descriptions match activations across many examples". You would see the same thing if the model had simply learned a good prior over what activations in this distribution tend to mean. My question was whether the description responds when you change one activation on purpose.

Before running anything I expected the adapter's geometry might settle this by itself, and while it does not, working out why turned out to be the useful part.

Method

Setup, and who did what

Llama 3.1 8B Instruct, layer 19 residual stream, using the authors' released adapter checkpoints. I trained nothing, so this reproduces their artefact rather than their training run. Scoring uses their embedding model, gte large, throughout. The final sweep is 134,406 generations, run on a single rented GPU for a few dollars of compute.

I think the attribution here should be explicit. The research question, the critique of the paper, and the experimental design are mine, and I wrote them up in an application I submitted before starting any of this work. I wrote the implementation with Claude Code, which accelerated the work considerably while still requiring continuous direction. Most of what follows came from interrogating outputs that did not look right. The two errors in What I got wrong are ones I caught by asking why a number looked the way it did.

Where the steering directions come from

I needed directions that mean something nameable, so the model has vocabulary to report them, and that demonstrably change behaviour, so I have an independent baseline. I used AxBench CONCEPT500, which gives me, for each of about 2000 concepts, example responses that express it and example responses that do not. Its concepts come from GemmaScope auto interp labels, so they sit in the same descriptive register the adapter was trained on. That matters, because a concept the model cannot name gives you a null result you cannot interpret.

I checked the data before using it, and that is where the first problem showed up.

Failure mode in the data

Every positive example is written in the same voice. An LLM generated AxBench's positives to express a concept, while the negatives are ordinary responses, which leaves the positives sharing a flowery register that the negatives lack. The word "akin" shows up in 17.2% of positives and 0% of negatives. Positives run 46% longer.

I measured how bad this is by training a classifier on some concepts and testing it on concepts it had never seen. It still separates positives from negatives 97% of the time, on style alone. A steering vector built as mean positive minus mean negative would encode "AxBench voice" rather than the concept. Worse, since style is a real and consistent direction, that vector would have passed my random direction control. I would have reported a confident false positive.

The fix is the same trick the paper uses for its own topic vectors. Subtract the average across all concepts, so whatever they share cancels and what makes each one distinctive survives. I also switched to building vectors from positives only rather than positives minus negatives, because the two sets of questions turn out to be completely disjoint. Differencing them imports an artefact from the prompt distribution.

What surprised me most was the gap between the text level check and the real thing. In word count space the shared component looked like 23% of a typical vector. Measured on actual Llama activations it was 96%. Every concept vector was very nearly the same vector, with gambling and plant virus classification sitting at 0.92 similarity. After subtracting the average they become essentially unrelated, the leftover similarities turn semantically sensible, and rebuilding each vector from a different half of its examples gives a 0.94 match. I think that lesson generalises. Dense activations carry register far more strongly than text statistics suggest, so check confounds in the space you actually intervene in.

How I scored "does this look like the concept"

The obvious method, measuring similarity between the description and the concept, is not trustworthy. That number drifts upward whenever the text becomes longer or vaguer, which means generic filler would register as success. I made it a multiple choice question instead. Compare the text to the right concept and to 40 other concept descriptions, then score the fraction of the alternatives it beats. Chance sits at 0.5. Generic drift lifts the right answer and the wrong answers together, so it cancels.

I tracked three further measures as checks. The first is a plain string match rate, which uses no embeddings at all, so the result does not rest entirely on one embedding model. The second and third are coherence measures, specifically the rate of repeated word pairs and how improbable the text appears to the unsteered model. The last is similarity to the description's original topic, which lets me observe the tradeoff rather than only the gain.

Finding · the reproduction holds, and the learned prior identifies nothing on its own while producing confident fabrications. "The bias accounts for 85% of the improvement" is fully compatible with the bias knowing nothing about the specific activation, which is what the authors say and what this measures.

2. Do the steering directions actually change behaviour

This step is what separates the rest of the work from a correlation. Before touching self interpretation at all, I added the direction into the residual stream during ordinary generation and measured whether the answers changed, and whether the model was still producing coherent English.

The failure mode worth noting is that at strength 2 the concept score sits near its maximum, precisely because the output has degenerated into nothing but concept keywords. The concept metric looks best exactly where the model has most thoroughly broken. Without the coherence measure I would have read that as my strongest result rather than the point of collapse.

Finding · the intervention is behaviourally real and monotone, but only strengths up to about 1 are interpretable. Past that I am measuring damage, so I restricted the rest of the analysis to that band.

3. Does the self description follow

The main experiment. For each activation I added the concept direction at seven strengths across 40 concepts, ran the result through the adapter, injected it, and generated six descriptions. Because the adapter normalises its input, adding a direction can only rotate it and never change its size, so no size confound can explain the result. That is a useful property of this adapter form that I did not expect going in.

I ran three control arms alongside, each aimed at a specific way the main result could be spurious.

Reading across, the concept arm climbs steadily and moves both ways. Push the activation toward the concept and the description follows. Push it away and the description moves away. This is easiest to read from the middle outward. With no nudge the model gets the topic right, and once I add a little the word Arabic survives while the domain slides from music to cinema, so the output blends the activation with the direction rather than replacing one with the other. Subtracting does the mirror image, since Arabic still survives while the domain slides toward textiles and away from film. If I push too far in either direction the topic washes out entirely and I am left with pure concept on one side and unrelated content on the other, which is exactly what the nudge alone control predicts and why I only trust the middle of the range.

Finding · the description tracks the activation, specifically and in both directions, and a random direction of the same size does not reproduce it. At a strength of 0.3 the concept arm sits at 0.49 while the nudge alone reference is already at 0.97, so the activation is still doing most of the work. I restricted the grid to a maximum strength of 1 for exactly this reason.

4. Does it follow at the right strength, and how large is the effect

Both experiments used the same strength scale and the same 40 concepts, so I can plot them against each other directly.

I expected the two to line up at roughly the same point. I did not expect them to lie almost on top of each other. Measuring where each reaches half its range gives 0.557 for behaviour and 0.517 for the description, and across all seven strengths the curves differ by an average of 0.022. This is the result I find most persuasive in the whole project, because a report that only registered gross changes would have produced a visibly flatter or delayed curve.

Finding · the self report shifts at the same intervention strengths that change the model's outputs, and by closely matching amounts, rather than trailing behind.

The harder question is how much of the output this actually accounts for, so I decomposed the variation between descriptions into the components that explain it, which are the shared constant every description carries, which activation it started from, which concept I used, the nudge itself, and plain sampling randomness.

I want to be careful reading this in both directions. The nudge accounts for under 1% of the variation and the activation's identity for 38%, so what a description mostly says depends on which activation it describes, not on what I added. Sixty percent of the remaining spread is sampling randomness at temperature 0.5, which is measurement noise rather than a competing explanation. A small share of total variation is also compatible with settling the specific question being asked. Descriptions vary along countless dimensions. The nudge moves them along one. Going from Arabic classical music to Arabic language cinema is not subtle, but it is one narrow move inside a space that already ranged across every topic in Wikipedia.

Finding · the effect points consistently in the right direction and holds up statistically, and it still is not what dominates what the model says. I think both halves of that need reporting.

What I got wrong

I found two of these only because a number did not look right and I followed it up. I think they are the most useful part of this project to document, since both are easy mistakes to make and neither one announces itself.

Error 1 · a control that could not have detected anything

My shared voice control returned 0.5000000000 at ten of the eleven strengths I tested. A genuine measurement does not behave that way, so I investigated.

The shared voice direction is a single vector used for every concept, so for any given activation it produces the identical description across all of them. I then scored that one description against each concept in turn, each against the others, which counts every ordered pair exactly once and forces the average to exactly a half. The number was arithmetic rather than measurement.

That control would have read 0.500 even if the direction had shoved every description toward one concept, and I had been treating it as my strongest control. The fix is to draw the comparison pool from concepts outside the set being tested, so wins and losses cannot cancel. Once I did that the arm gave a genuine flat result instead of a forced one. The general lesson is that a rank against alternatives metric needs its targets and its alternatives drawn from separate sets.

Error 2 · a filter that selected against its own effect

I gated concepts on staying coherent across the whole range of strengths, including the extremes I then excluded from interpretation anyway. Only 11 of 60 concepts survived. If you gate on the range you actually analyse, all 60 qualify.

The filter was not merely wasteful, it was biased. Steering hard and breaking the model at high strength are the same phenomenon, so "still coherent at strength 2" preferentially kept the concepts that do not do much. Concepts that survived the strict gate had a median behavioural effect of 0.283. The ones it excluded had 0.526. My filter was quietly selecting against the effect I was trying to measure, and it cost me roughly half the observable effect size.

There is a smaller one I should mention too. I initially described the zero vector experiment as reframing the paper's claim about the bias, which it does not do, since the authors already run that test and already conclude that the bias supplies format while the activation supplies meaning. My result puts a number on half of a claim they were already making, and I fixed the write up once I went back and reread their discussion section.

Limitations and future work

  • This is a sensitivity test, not a causal one. Steering vectors are not clean semantic representations, so showing the description responds to one is weaker than showing it correctly reports a change whose internal role we already understand. Next step. Intervene on a feature or circuit whose causal role is independently established, such as the name mover heads in the IOI circuit, and test whether the self report describes that.

  • I selected favourable concepts twice. First for being clean in the data, then for steering well without breaking fluency. These results describe the favourable case rather than the average concept. Next step. Report the full distribution across all screened concepts, including the ones that barely steer.

  • One confound in the data survives. AxBench's positive and negative examples answer completely different questions, and those questions were selected to suit their concept, which leaves the vector blending the concept in the response with the topics of its prompts. Subtracting the average cannot fix this, because the question content is itself tied to the concept. Next step. Add a control arm built from the questions alone, to bound how much of the effect comes from prompt topic.

  • I only tested one setup. Everything here runs on a single model at a single layer with one adapter architecture, so I do not know how far it generalises. The adapters trained on sparse autoencoder features give their activation term less than half the relative size that the topic adapter does, which I would expect to change the answer. Next step. Repeat on the Goodfire and Llama Scope adapters, and at a second layer.

  • Small effect size and a modest sample. Confidence intervals over concepts are wide because the concept is the unit of replication and there are not many of them. Next step. Run more concepts, which is cheap now that the coherence gate is fixed. That gate was the binding constraint, not compute.

  • Scoring leans on one embedding model. The same embedder scores the screen that selects concepts and the sweep that measures the effect. My string matching check agrees with it, which is reassuring, but the two are not independent enough for me to rely on. Next step. Score with a second embedder and an LLM judge.
